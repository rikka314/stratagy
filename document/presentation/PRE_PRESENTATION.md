## 二、策略逻辑优化（2.5分钟）

### 【演示：单股分析 - AAPL】

### 问题诊断

寒假初期发现策略表现极差：
- **组合收益**：13.41%
- **买入持有基准**：178.27%
- **根本原因**：大部分时间空仓，错过主要行情

### 核心改进

**1. 入场逻辑改为计数制**
- **优化前**：5个信号全部满足（AND 逻辑）→ 门槛过高
- **优化后**：5个信号中至少满足 N 个（默认 3）
- 5个入场信号：因子评分、趋势(EMA)、强度(ADX)、RSI、MACD

**2. 出场逻辑改为计数制**
- **优化前**：4个信号任一触发（OR 逻辑）→ 频繁止损
- **优化后**：4个信号中至少满足 N 个（默认 2）
- 4个出场信号：评分过低、趋势反转、RSI越界、MACD转弱

**3. 降低仓位门槛**
- 满仓门槛从 ≥95分位 → ≥80分位
- 60%仓位从 ≥75分位 → ≥55分位
- 提升资金利用率

**4. 防过拟合机制**
- 训练集内部拆分子验证集（70/30）
- 目标函数 = 0.4×训练分 + 0.6×验证分 - 0.3×|gap|
- L2 正则化惩罚极端参数

### 【演示：高级策略搜索】
> 点击"搜索方法"下拉框 → 展示 3 种算法

**三种智能优化算法**：
1. **贝叶斯优化**（Optuna）
   - 用高斯过程建模参数-性能关系
   - 智能采样高潜力区域，比网格搜索快 100 倍
   - 适合：精确优化，10-50 次迭代

2. **遗传算法**（Genetic Algorithm）
   - 模拟生物进化：变异 + 交叉 + 适者生存
   - 多核并行，种群规模 50，精英保留 top 5
   - 适合：全局搜索，跳出局部最优

3. **随机搜索**（Random Search）
   - 完全随机采样参数空间
   - 作为基线对比，验证智能算法的提升

> 演示：选择"遗传算法" → 50 次迭代 → 显示训练集/验证集分数 → 过拟合风险指示器

### 预设策略系统

新增 4 种预设策略模板：
- **趋势跟随（保守）**：宽松入场、快速止损
- **均衡策略（默认）**：攻守兼备
- **动量突破（激进）**：严格筛选、放大利润
- **自定义参数**：完全手动调节

## 三、代码架构重构（1.5分钟）

### 重构动机

- **原代码**：单文件 5875 行，功能耦合严重
- **问题**：AI 辅助时上下文窗口不足、难以维护

### 模块化设计

拆分为 **15 个模块文件**：

```
app.py              (~120 行)   # 入口路由
core/               # 核心逻辑包（10 个文件）
├── config.py       # 常量配置
├── data.py         # 数据处理
├── indicators.py   # 技术指标
├── signals.py      # 策略信号
├── backtest.py     # 回测引擎
├── optimizer.py    # 参数优化（贝叶斯/遗传/随机）
├── portfolio.py    # 投资组合模拟
├── visualization.py# 图表生成
└── utils.py        # 工具函数
ui/                 # UI 模块包（4 个文件）
├── sidebar.py      # 侧边栏控件
├── single_stock.py # 单股分析页
└── multi_stock.py  # 多股对比页
```

### 重构收益

- **可测试性**：5 个纯计算模块可独立测试
- **关注点分离**：数据/逻辑/UI 三层解耦
- **AI 协作友好**：每个模块 ~100-800 行，易于理解
- **原文件备份**：app_original.py 保留完整历史

## 六、AI 协作开发（1.5分钟）

寒假的整个开发过程中，AI 不仅是一个工具，更像是一个**结对编程的搭档**。我想分享一下我是如何使用 AI 参与工作的。

### 工具链

- **VS Code + GitHub Copilot**：代码编辑环境，AI 实时辅助编码
- **Cursor**：用于复杂功能的对话式开发
- AI 助手可以直接通过 SSH 操作服务器、部署代码

### 我的 AI 协作方法论

**核心原则：我做决策，AI 做执行**

| 环节 | 我做的事 | AI 做的事 |
|------|---------|----------|
| **需求分析** | 诊断策略表现差的原因，提出"计数制"改进思路 | 将思路转化为具体代码实现 |
| **架构设计** | 决定模块拆分方案（core/ + ui/） | 执行拆分、处理依赖关系 |
| **部署运维** | 选择云服务商、规划网络架构 | 编写 Nginx 配置、systemd 服务文件 |
| **Bug 排查** | 描述现象（如"strategy 页面空白"） | 定位原因、提出修复方案 |
| **知识学习** | 提问"什么是 L2 正则化""贝叶斯优化原理" | 用我能理解的方式解释概念 |

### AI 驱动的开发效率

**一个典型的功能迭代周期**：
```
我提出需求（如"加一个防过拟合机制"）
    ↓ 30 秒
AI 输出方案（子验证集 + L2 正则化 + gap 惩罚）
    ↓ 我判断方案合理性
AI 生成代码 + 自动部署到服务器
    ↓ 5 分钟
我验证效果，提出调整
    ↓
一轮迭代完成
```

**传统方式**可能需要**几天学习 + 几天实现**，AI 协作让我在**几小时**内完成。

### AI 辅助的关键决策案例

## 备用 Q&A

**Q1：为什么选择 Streamlit 而不是 Flask/Django？**
> Streamlit 专为数据应用设计，内置图表/缓存/会话管理，开发效率高。Flask 需要手写前端和状态管理。

**Q2：贝叶斯优化相比网格搜索的优势？**
> 贝叶斯优化用高斯过程建模参数-性能关系，智能采样高潜力区域。网格搜索盲目遍历，25 个参数的搜索空间需要数十亿次计算。

**Q3：遗传算法的具体实现？**
> 种群 50 个个体，每代：(1) 评估适应度（夏普比率），(2) 精英保留 top 5，(3) 锦标赛选择父代，(4) 单点交叉+高斯变异生成子代。多核并行加速评估。

**Q4：防过拟合机制的效果如何？**
> 实测训练-验证夏普差距从 1.5+ 降至 0.3-0.5，测试集表现更稳定。

**Q5：服务器成本？**
> 火山引擎学生机，4GiB RAM + 40GiB SSD，约 ¥100/年（已续费至 2027-02-10）。

**Q6：如果 Streamlit 崩溃怎么办？**
> systemd 配置了自动重启（5秒延迟），并且可以通过 `ssh stratagy "journalctl -u stratagy -n 50"` 查看日志诊断。

**Q7：用 AI 写代码，你自己学到了什么？**
> AI 负责具体的代码编写，但我必须理解每一个技术决策的 why——为什么选择计数制而不是 AND 逻辑、为什么需要防过拟合、为什么要模块化。我提需求、做决策、验证结果，AI 是加速器而不是替代品。这个过程中我学到了量化策略、云部署、前端开发、Nginx 配置等实际技能。

**Q8：AI_CONTEXT.md 是什么？为什么要写这个？**
> 这是一份 2000 token 的项目浓缩摘要，替代 AI 阅读 43000 token 的源码。AI 的上下文窗口有限，给它一份精炼的"项目说明书"，它就能快速理解项目并准确修改代码。这也是模块化重构的动机之一——单文件太大，AI 无法一次性理解。

# JavaScript 前端迁移

> 2026-09-13；实施与验收清单。已完成项以末尾验证记录为准。

## 目标与边界

浏览器页面迁移为 JavaScript，Python 继续负责行情、指标、信号、回测、评估和组合计算。沿用 `/strategy` 及现有公开页面路径。旧 Streamlit 入口保留为显式回退方式。

用户指定参考 [gfm156.com](https://gfm156.com/) 的风格，并随后明确纠正：布局和内容应与原网站相同。原首页市场舞台、入口左右分栏、基础信息/策略切换、控制台/结果、研究与报告阅读结构均须保留。只更换框架、字体、配色等视觉细节，不增加宣传章节或删减原内容。

## 实施顺序

1. 冻结已有计算入口和回归基线；不把策略算法翻译为 JavaScript。
2. Python API 封装已有计算流程，隔离每个任务的状态，校验上传、参数与结果序列化。
3. JavaScript 页面消费 API，覆盖首页、单股、多股、研究证据、报告及本地监控。
4. 更新本地启动、构建、健康检查和部署模板，保留 `/strategy` 子路径。
5. 验证真实 CSV 计算、前后端连通、失败状态、路由刷新、移动布局、语言与主题。

## 验收重点

- 相同 OHLCV 与参数复用原 Python workflow；不能用演示曲线冒充计算结果。
- 长计算有任务状态，失败可见；adaptive 降级仍能展示结果与原因。
- 表单修改不会自动重复运行计算；上传与行情标的切换不会误用旧结果。
- 研究结论继续消费冻结证据，缺失产物保持缺失状态。
- 刷新、返回、深链接与结果导出可用。
- 构建产物和 API 均包含在部署清单，生产发布单独执行。

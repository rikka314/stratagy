## 1. 当前背景与总目标

### 1.1 当前项目状态

- 前 5 周已基本完成数据层、A 股支持、5 模型评估、FSM/ML-SM、单股页策略工作流重构。
- 当前主要短板已不再是核心算法功能，而是：
  - 页面结构混乱
  - 入口路径不清晰
  - UI 风格不统一
  - 图表可读性与信息层级不足
  - 单股与多股页面缺少独立入口体验
- 当前应用仍是单一 Streamlit 入口，主要依赖侧边栏决定页面模式；这和新的产品目标不匹配。

### 1.2 新阶段总目标

- 把网站前端体验重构成完整的三层路径：
  - 首页 `/strategy`
  - 单股入口页 `/strategy/stock-analysis`
  - 多股入口页 `/strategy/stocks-analysis`
- 把单股与多股都拆成“入口页”和“主分析页”两段式体验。
- 用一套统一的前端风格标准管理颜色、字体、图表、动效、双语和昼夜主题。
- 产出 Codex 和 Cursor 的前端 skill / 规则，后续前端任务全部遵守。
- 保持核心策略接口尽量不变，优先重排 UI 中具体模块的位置和交互，不随意推翻后端。
- 服务器不再长期存放股票数据，尽量改成按需拉取最新数据，本地上传只作为临时分析输入。
- 在 W8 完成双语、昼夜、导出、响应式、部署和技术验收。
- 在 W9 完成最终报告、引用整理、答辩准备和 zip 提交包收口。

### 1.3 计划完成标准

- 用户直接访问 `www.gfm156.com/strategy` 能看到首页，而不是旧的分析页面。
- 单股和多股都有独立入口页与主分析页。
- 单股和多股的主分析页都符合统一风格，且与图一到图五的视觉逻辑明显对齐。
- 现有策略链路和关键接口保持可用，不因为 UI 改版导致工作流报废。
- W8 完成完整回归、最终部署和技术验收记录。
- W9 产出最终报告 HTML、课程要求对应说明、references、答辩材料和提交 zip 清单。

### 1.4 课程交付补充目标

- 最终报告必须明确回答：
  - 项目要解决什么金融数据分析问题

  - simple baseline 与 proposed model 的差异和结果对比

## 8. 单股票基础信息区计划

### 8.1 总体结构

- 右侧：图表信息

### 8.2 文字区必须包含

优先检查是否能从 AkShare 获取，获取不到则显示空值占位：

- 当前股票价格
- 最新一天最高价
- 最新一天最低价

- 市值
- 流通
- 市盈
- 量比
- 换手

### 8.3 图表区必须包含

- K 线图
- 下方小图指标区

### 8.4 图一带来的补充要求（K 线视觉规格）

图一体现的是“高密度证券软件风格 K 线图”，需要在计划中明确以下实现约束：

- K 线图主图占整个图表容器的主要高度，小图指标区高度约为主图的 25% 到 30%
- 顶部必须有周期切换条，至少明确显示：
  - 日 K
  - 周 K
  - 月 K
- 不做分时、120 分钟、五日等扩展功能，但视觉上可以保留“顶部切换条”的结构感
- K 线图上方需要显示均线图例和均线数值，表现方式参考图一的密集信息条
- K 线形态使用红绿实体柱和上下影线，线条不能过粗
- 坐标轴和网格线风格应轻、细、淡，避免压住 K 线主体
- 主图底部不是按钮，而是滑动条/缩放条，用于查看全部历史数据
- 滑动条需要支持丝滑拖动，默认查看全部数据，但允许用户局部放大
- 未选择训练时间前，在图表区域明确显示“目前没有选中训练集”
- 选择训练时间后，训练集图与完整数据图使用同一组件，只是显示范围被裁剪

### 8.5 小图指标区规则

- 默认显示 MACD
- 点击小图后切换到 RSI
- 再点击切换到成交量
- 再点击回到 MACD
- 与主图滑动条同步

### 8.6 基础信息区验收

- 左文右图层级明确
- 文字信息足够“说明股票状态”，不再只靠图片
- K 线图可看性和信息量兼顾
- 未选训练集与已选训练集状态都能正确显示

## 9. 单股票策略区计划

### 9.1 总体结构

- 左侧：模型控制台
- 右侧：模型结果区

### 9.2 左侧控制台内容

顺序固定为：

- 训练时间区间选择
- 模型选择
- 模型配置
- 生成模型
- 保存模型
- 从保存模型中选择一个或多个模型

规则：

- 默认训练时间区间为两年
- 保存模型与后面的策略比较共用同一保存池
- 但“用于当前使用”和“用于比较展示”语义必须分开

### 9.3 右侧结果区内容

未生成前：

- 显示“模型还没准备好”

生成后：

- 左侧较大区域：主结果图或主结果文本
- 右侧较窄区域：小按钮切换区

主结果必须至少支持以下内容切换：

- 当前推荐操作
- 夏普比率、过拟合率等结果摘要
- 净值与回撤和月度收益图合体的图
- 买卖点图

### 9.4 图二和图三带来的补充要求（策略结果视觉规格）

#### 图二：净值/回撤 + 月度收益热图组合

计划中补充以下硬性要求：

- “净值与回撤和月度收益图合体的图”不是一句抽象描述，而是固定为上下组合结构：
  - 上方：净值曲线
  - 中间：回撤曲线
  - 下方：月度收益热图
- 净值曲线和回撤曲线属于同一张主图的上下双子图，而不是两个完全分开的卡片
- 月度收益热图应放在这组图下方，作为第三段，不单独漂移到别处
- 主色调参考图二的浅金色/暖色细线风格，整体需要更克制、更轻
- 热图颜色应该明确表示正负收益，且旁边要有颜色刻度或图例

#### 图三：核心指标摘要区

计划中补充以下要求：

- 在“各种率”的展示里，不应只是一个数值列表，而要有一块固定的“核心指标”摘要区
- 该区域采用横向 3 列或等价布局，至少展示：
  - 累计收益率
  - 年化收益率
  - 最大回撤
  - 夏普比率
  - 胜率
  - 盈亏比
- 每列上方是指标名，下方是当前模型结果
- 视觉上参考图三的“标题 + 分组指标”的结构，优先做简洁文本区，而不是复杂卡片堆砌

### 9.5 Walk-Forward

- 放在策略区结果部分下方
- 可以选择对哪个或多个模型做回测
- 当前阶段不并入“策略比对模式”的主图切换区，保持相对独立

**兜底：**

- W6 内就把真实 URL 路由纳入计划
- 不把部署问题拖到 W8 才处理

**兜底：**

- 保持 `core/` 逻辑不动
- 单股策略区必须复用 W5 工作流，不另起一套

**兜底：**

- W9 单独留给报告、references、答辩和 zip 打包，不再和 UI 精修混排

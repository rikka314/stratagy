## 技术边界与工程约束

### 1. 核心接口尽量不动

- `core/data.py`、`core/utils.py`、`core/signals.py`、`core/backtest.py`、`core/evaluation.py`、`core/fa_filter.py`、`core/ml_filter.py` 尽量只做适配，不做语义推翻。
- W5 刚冻结的 `StrategyRequest / StrategyArtifact / strategy_workspace` 继续视为单股策略主分析页的后端协议，不允许为了做 UI 重新改写其核心语义。
- 入口页如果需要新增“市场/股票/上传/大盘/推荐股票”的组合状态，优先通过 UI 层 state 组合，不先修改核心计算接口。

### 2. 路由要变，但不做重型前端框架迁移

- 目标路径：
  - `/strategy`
  - `/strategy/stock-analysis`
  - `/strategy/stocks-analysis`
- 由于当前项目仍是单个 Streamlit 应用，W6 需要先冻结“如何在 Streamlit 中实现页面路由”的统一方案。
- 可接受的实现方向：
  - query params + session route
  - 页面壳层 router
  - 单应用内页面状态机
- 本周不做的事：迁移到 React / Next.js / FastAPI + 前后端分离。

### 3. 数据获取方式要从“缓存为主”改成“按需拉取为主”

- 服务器端默认不长期保存股票 CSV。
- 允许保留：
  - 临时缓存
  - 会话态缓存
  - AkShare 拉取结果的短期缓存
- 本地上传股票数据仍保留，但它只是一条输入路径，不再是主要依赖路径。

### 4. AkShare 数据接口现状（本周已做的初步核验）

- 已确认当前项目虚拟环境中存在以下接口：
  - `index_zh_a_hist`
  - `stock_zh_index_daily_em`
  - `index_global_hist_em`
  - `index_us_stock_sina`
  - `stock_zh_a_spot_em`
  - `stock_us_spot_em`
  - `stock_us_hist`
- 由此可推定：
  - A 股大盘指数历史/日 K 数据有现成接口
  - 美股三大指数历史数据有现成接口可接
- 仍未完全冻结的点：
  - “昨天涨幅最大的十只股票”是否存在稳定直接接口
  - 若无直接接口，W6 必须二选一冻结：
    - 用实时涨幅榜替代
    - 用上一交易日涨停/强势池替代

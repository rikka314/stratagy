# 单股页策略工作流重构总说明

> 目标目录：`plan/model-change/`  
> 文档定位：作为本轮单股页策略逻辑重构的总入口，先定义完整工作流，再配合 `day1-3.md`、`day4-5.md`、`day6-7.md` 逐日实施。  
> 关联模块：`ui/single_stock.py`、策略编排层、`st.session_state`、下游评估/图表区

---

## 1. 重构背景

当前单股页的核心问题不是“模型不够多”，而是**模型关系、页面顺序、状态管理都混在一起**：

- 页面加载时就一次性计算多个模型，用户还没选模型，结果区已经出现。
- `策略建议`、`高级策略搜索`、`测试集表现`、`交易信号` 是线性堆叠的，但它们本质上依赖前面的策略选择结果。
- 基线模型、搜索模型、FSM、ML 过滤没有严格按层级组织，导致用户看到的是“功能列表”，不是“策略生成流程”。
- 下游区块大量依赖一次性全模型 payload，而不是依赖“当前已经生成好的策略实体”。

这轮重构的目标不是做新模型，而是把**单股页从一组区块，改成一条明确的策略工作流**。

---

## 2. 目标工作流

### 第一层：先选模型大类

用户进入策略区后，先只看到模型选择框：

- `Baseline`
- `Search`

此时页面不展示策略建议、搜索结果、测试集表现、买卖点等结果区。

### 第二层：在 Search 下选择基础模型

如果用户选 `Baseline`：

- 再选择 `Naive / Mean / Drift`
- 选完后直接生成策略
- 不出现 `FA`、参数搜索、`ML` 控件

如果用户选 `Search`：

- 再选择 `SM / FSM`
- `SM` 走普通搜索模型路径
- `FSM` 必须先做 `FA`，再进入后续步骤

### 第三层：可选增强步骤

对 `SM` 和 `FSM` 都允许再走两个增强步骤：

- 参数搜索
- `ML` 信号过滤

它们在 UI 上都可以是可选项，但**执行顺序固定**：

- `SM`：`SM基础 -> 可选搜索 -> 可选ML`
- `FSM`：`FA -> FSM基础 -> 可选搜索 -> 可选ML`

如果用户同时勾选搜索和 `ML`，则 `ML` 永远作用在“最新上游结果”上，不允许跳过上游直接训练。

---

## 3. 核心接口

### `StrategyRequest`

表示一次用户发起的策略生成请求，只保存“要跑什么”：

- `family`: `baseline` 或 `search`
- `baseline_kind`: `naive / mean / drift`
- `search_base`: `sm / fsm`
- `use_search`: 是否启用参数搜索
- `search_method`: `bayesian / random / genetic`
- `use_ml`: 是否启用 `ML` 过滤
- `ml_model_type`: `logistic / lgbm`

约束：

- 不保存回测结果
- 不保存图表对象
- 不直接当作下游展示数据源

### `StrategyArtifact`

表示一次已经生成完成、能进入后续分析和比较的策略实体，至少要包含：

- `id`
- `display_label`
- `pipeline_lineage`
- `params_snapshot`
- `train_sim_df`
- `test_sim_df`
- `trades_df`
- `eval`
- `equity_series`
- `returns_series`
- `ml_quality`

约束：

- 下游所有图表和比较都统一读 artifact
- artifact 一旦生成，当前策略立即可见

### `strategy_workspace`

会话级状态容器，固定包含：

- `context_key`
- `current_artifact`
- `saved_artifacts`

含义：

- `current_artifact`：当前最新生成的最终策略
- `saved_artifacts`：用户显式保存的会话内策略快照
- 刷新页面后失效，不做持久化

## 4. 页面结构重排

### 旧结构

- 策略建议
- 高级策略搜索
- 搜索结果
- 测试集表现
- Walk-Forward
- 测试集交易信号

问题是：这些块默认都挂在页面上，但用户并没有完成策略生成。

### 新结构

重构后主区策略段改成 5 个连续部分：

1. `策略工作台空状态`
- 只显示模型选择和步骤提示

2. `模型配置区`
- 按层级显示控件
- 用户没走到下一步时，下游控件不出现

3. `生成区`
- 统一使用一个“生成策略”按钮
- 页面加载时禁止自动计算全模型

4. `当前工作流比较`
- 只展示本次链路相关结果
- 示例：
- `SM + Search + ML` 时展示 `SM基础`、`SM+Search`、`SM+Search+ML`
- `FSM + Search + ML` 时展示 `FSM基础`、`FSM+Search`、`FSM+Search+ML`

5. `策略库与下游分析`
- 统一读取 `current_artifact + saved_artifacts`

---

## 5. 下游分析统一改造

下游分析不能再依赖页面启动时的一次性全模型载荷，而要统一读取 artifact。

第一批纳入改造的区块：

- 回测净值/回撤
- 月度或周期收益热图
- 指标比较表
- 买卖点查看

其中：

- `equity_series` 用于净值和回撤
- `returns_series` 用于收益热图
- `eval` 用于指标比较表
- `train_sim_df / test_sim_df` 用于训练集/测试集买卖点切换

约束：

- 当前策略默认立即进入下游分析
- 保存策略后，才进入会话内的长期比较列表
- 多策略选择器不再写死固定模型名，而是从 artifact 列表动态生成

## 6. 状态边界与失效规则

### 保存语义

- 当前策略生成后立即可见
- 点击保存后，变成 `saved_artifact`
- 保存只是会话内冻结快照，不做持久化

### 清空语义

以下任一变化，全部清空当前策略和已保存策略：

- 股票变化
- 市场变化
- 上传数据变化
- 日期范围变化
- 训练集比例变化

### 失败语义

- `FA` 失败：保留上游可用结果，不让整条链路崩掉
- 搜索失败：保留基础 `SM / FSM`
- `ML` 失败：保留无 `ML` 的上游结果，并显示明确提示

## 7. 第一周范围边界

本轮重构只做单股页策略工作流，不扩散到整站。

### 本周必须完成

- 策略层级关系固定化
- 编排层从 UI 中拆出
- 主区顺序重排
- artifact 接管下游分析
- 会话内策略保存与比较
- 状态边界和回归测试口径

### 本周明确不做

- `Walk-Forward` 策略库化
- 自定义保存名称
- 新的视觉大改版
- 多股页同步重构

---

## 8. 推荐阅读顺序

1. 先读本文件，理解完整工作流和边界
2. 再读 `day1-3.md`，完成规则、接口、主区顺序
3. 再读 `day4-5.md`，完成 artifact 接管和状态边界
4. 最后读 `day6-7.md`，完成测试、验收和收口

这样可以保证后续实现不是“边写边想”，而是按已经定好的工作流推进。

# 两个月交付计划：A 方向策略系统增强版

## 1. 项目目标定义

### 项目定位
在 **8 周固定工期** 内，把当前项目做成一个 **可演示、可验证、可展示的量化策略分析系统增强版**，重点不是追求最复杂模型，而是形成完整闭环：

- [ ] 支持 **美股 + 中国 A 股** 的基础数据分析与策略回测
- [ ] 保留现有规则/因子/仓位逻辑，并加入 **一个可验证的机器学习增强模块**
- [ ] 提供 **简单但完整的策略评估功能**
- [ ] 完成一轮 **UI 优化**，让系统更像正式作品而不是实验页面
- [ ] 最终形成可运行系统 + 使用文档 + 方法说明 + 演示材料

### 最低可交付版本
- [ ] 现有策略框架稳定运行
- [ ] 新增 A 股数据接入与单股分析
- [ ] 新增一个 ML 增强模块：**信号过滤**
- [ ] 新增基础评估页：收益、回撤、夏普、胜率、基准对比
- [ ] UI 做一轮基础整理：布局、配色、指标卡、图表统一
- [ ] 有一份可交付说明文档

### 标准可交付版本
- [ ] 美股/A 股双市场支持
- [ ] ML 增强模块完成：**信号过滤 + 市场状态识别（二选一完成核心，另一个至少原型）**
- [ ] 策略评估模块支持多维分析：区间表现、参数对比、策略版本对比
- [ ] UI 完成关键页面优化：首页/侧边栏/单股页/评估页
- [ ] 有可复现实验结果和演示脚本

### 理想可交付版本
- [ ] 在标准版基础上，再加入一个 **新策略模式**
- [ ] ML 模块支持概率分层仓位或因子打分增强
- [ ] 评估模块支持策略对比报告导出
- [ ] UI 达到“作品集展示级”

## 2. 总体范围规划

### A. 策略核心功能
- [ ] **必须完成**：现有规则策略稳定化、A 股支持、回测一致性检查  
原因：这是整个项目的底座，没有它其他模块没有意义。
- [ ] **建议完成**：新增一个全新策略模式  
建议做一个轻量策略，如“均线趋势 + 波动过滤”或“均值回归 + RSI/布林带”
- [ ] **可选完成**：多标的横截面排序增强  
两个月内容易扩散范围。
- [ ] **不建议做**：复杂多资产组合框架重构  
超出单人 8 周合理范围。

### B. 机器学习增强功能
- [ ] **必须完成**：一个可验证的 ML 增强模块，优先 **信号过滤**
- [ ] **建议完成**：市场状态识别，驱动策略开关或阈值切换
- [ ] **可选完成**：仓位调整 / 多因子学习
- [ ] **不建议做**：LSTM、Transformer、强化学习、端到端黑盒预测  
原因：数据、时间、验证成本都不适合 8 周项目。

### C. 策略评估功能
- [ ] **必须完成**：基础收益和风险指标、基准对比、参数/版本对比
- [ ] **建议完成**：分区间表现、不同市场状态表现
- [ ] **可选完成**：简易报告导出
- [ ] **不建议做**：复杂归因系统、生产级审计报告

### D. UI 优化与美化
- [ ] **必须完成**：信息结构整理、关键页面统一视觉、图表层级优化
- [ ] **建议完成**：首页摘要卡、评估页仪表盘、操作反馈
- [ ] **可选完成**：导出页优化、深色主题、动画
- [ ] **不建议做**：大规模重做全部页面、复杂前端组件体系

### E. 测试、文档、演示准备
- [ ] **必须完成**：核心流程测试、使用文档、演示脚本
- [ ] **建议完成**：方法说明、实验记录
- [ ] **可选完成**：视频演示
- [ ] **不建议做**：过度补单元测试而拖慢主交付

## 4. 机器学习增强模块计划

### 两个月内最值得做的增强点
**第一选择：信号过滤**  
这是最适合你当前项目的 ML 切入点。

### 第一优先级：信号过滤
- [ ] **目标**：减少假信号，提高胜率和回撤质量
- [ ] **输入特征**：`factor_score`、`factor_percentile`、10 因子分量、RSI、MACD、ADX、ATR/close、volume_ratio、drawdown、trend_ok、entry_count、市场指数收益/波动
- [ ] **输出标签**：当前开仓信号未来 5 或 10 日是否获得正超额收益
- [ ] **推荐模型**：Logistic Regression、LightGBM
- [ ] **实现难度**：低到中
- [ ] **预期收益**：最可能在 8 周内做出可解释增量
- [ ] **风险**：标签设计不合理会直接失效

### 第二优先级：市场状态识别
- [ ] **目标**：识别趋势/震荡/高风险环境，决定是否放行策略
- [ ] **输入特征**：指数收益、指数波动率、ADX、宽度、成交量环境、回撤状态
- [ ] **输出标签**：市场状态类别，或是否适合启用主策略
- [ ] **推荐模型**：聚类、树模型、简单分类器
- [ ] **实现难度**：中
- [ ] **预期收益**：增强稳定性，改善不同市场阶段表现
- [ ] **风险**：状态定义漂亮但未必可交易

### 可选增强项：仓位调整
- [ ] **目标**：根据信号质量动态调仓
- [ ] **输入特征**：信号强弱、市场状态、近期波动、近期策略表现
- [ ] **输出标签**：建议仓位档位
- [ ] **推荐模型**：分类器或概率分层
- [ ] **实现难度**：中
- [ ] **预期收益**：提升资金使用效率
- [ ] **风险**：噪声放大

### 两个月内不建议碰
- [ ] LSTM / Transformer
- [ ] 强化学习
- [ ] 复杂模型融合
- [ ] 端到端黑盒收益预测

## 5. 简单的策略评估功能应该怎么做

- [ ] 年化收益
- [ ] 最大回撤
- [ ] 夏普比率
- [ ] 胜率
- [ ] 盈亏比
- [ ] 换手率
- [ ] 策略 vs 买入持有

- [ ] 回撤曲线
- [ ] 月度收益热图
- [ ] 收益分布图

### 最适合先做的分析功能

**总体判断**

适合加入机器学习，但最合理的定位是`辅助增强模块`，不是立刻改成黑盒核心引擎。

我的判断很明确：
- 对个人开发者，最优路线是`策略为主，机器学习为辅`
- 可以逐步过渡到“机器学习驱动某些子模块”，但不建议直接过渡到“全系统黑盒驱动”
- 机器学习最容易明显提升项目质量的场景：`信号过滤`、`市场状态识别`、`多因子加权/排序`、`仓位控制`
- 机器学习最容易只增加复杂度的场景：`直接预测原始价格`、`深度学习端到端替代全部规则`、`小样本上堆复杂模型`

一句话：`先让 ML 决定“什么时候信号可信、应该给多大仓位”，而不是先让 ML 直接决定“买什么、什么时候买、买多少、什么时候卖”。`

**机器学习可以嵌入哪些位置**

| 嵌入点 | 解决的问题 | 推荐方法 | 难度 | 预期提升 |
|---|---|---|---:|---|
| 信号过滤 | 原策略信号太多、假信号多 | Logistic / LightGBM | 低 | 最现实，直接提升胜率与回撤 |
| 多信号加权 | 固定权重不稳，市场变了还在用旧权重 | LightGBM / Elastic Net | 中 | 比手工权重更自适应 |
| 因子筛选 | 指标太多、冗余高 | L1、Permutation importance、相关聚类 | 低 | 降噪，减轻过拟合 |
| 因子降维 | 高相关因子重复表达同一信息 | PCA / 特征聚类 | 低中 | 提升稳健性，但解释性下降 |
| 市场状态识别 | 趋势/震荡/高波动下同一策略表现不同 | 聚类 / HMM / 分类树 | 中 | 很适合做策略切换 |
| 择时判断 | 是否适合开仓 | Logistic / GBDT | 中 | 适合和原有入场条件叠加 |
| 仓位控制 | 有信号时仓位过大或过小 | 回归 / 分箱分类 | 中 | 利用你现有 `target_position` 接口很自然 |
| 风险预警 | 回撤前缺乏保护 | 分类模型预测高风险状态 | 中 | 降低尾部风险 |
| 止损止盈优化 | 固定 ATR 倍数不适应环境 | 回归 / 策略选择模型 | 中高 | 有用，但应晚于信号过滤 |
| 参数自适应 | 不同市场环境最优参数不同 | 状态模型 + 预设切换 | 中高 | 比“实时搜索最优参数”更现实 |
| 标的打分排序 | 多股票里先做优先级 | LightGBM Ranker / 回归排序 | 中高 | 如果你扩展多股面板，价值很高 |
| 组合优化 | 多信号、多标的分配 | 先规则，后 ML 辅助 | 高 | 单人不建议早做 |

最推荐先做的 4 个位置：
- `信号过滤`
- `市场状态识别`
- `多因子加权/打分`
- `仓位调整`

**方法路线详细分析**

| 方法 | 适合做什么 | 单人是否适合 | 数据要求 | 解释性 | 主要陷阱 | 优先级 |
|---|---|---|---|---|---|---|
| 逻辑回归 | 信号过滤、择时、风险状态 | 很适合 | 低 | 高 | 线性假设过强 | 很高 |
| 随机森林 | 非线性分类基线 | 适合 | 中 | 中 | 易过拟合、概率不稳 | 中 |
| XGBoost / LightGBM | 因子打分、排序、过滤、仓位回归 | 最适合 | 中 | 中 | 调参过多、泄漏后“很强” | 最高 |
| CatBoost | 加入 `symbol/sector/regime` 这类类别特征时很好 | 适合 | 中 | 中 | 类别编码若时序处理错会泄漏 | 高 |
| SVM | 小样本二分类可试 | 一般 | 中 | 中低 | 慢、难扩展、概率校准麻烦 | 低 |
| KNN | 几乎不建议 | 不适合 | 中 | 低 | 对噪声和尺度极敏感 | 很低 |
| 聚类 | 市场状态识别、策略分段 | 适合 | 低中 | 中 | 聚出来的状态不一定可交易 | 高 |
| PCA / 降维 | 压缩高相关特征 | 适合 | 低 | 低 | 可解释性差，容易丢掉直觉 | 中 |
| MLP | 非线性 tabular baseline | 可试 | 中高 | 低 | 对特征工程和正则更敏感 | 中低 |
| LSTM | 长窗口时序建模 | 谨慎 | 高 | 低 | 单股日频样本太少 | 低 |
| Transformer / TFT | 多序列、多变量长依赖 | 不建议早做 | 很高 | 低中 | 实现重、算力重、验证慢 | 很低 |
| 强化学习 | 联合决策仓位与交易 | 不建议 | 很高 | 很低 | 奖励设计和回测环境极易失真 | 最低 |
| 集成学习 / Stacking | 多模型融合、元模型 | 适合第二阶段 | 中 | 中低 | 叠加复杂度快于增益 | 中高 |
| 状态分类模型 | 不同 regime 切不同规则或阈值 | 很适合 | 低中 | 中 | 状态定义不稳定 | 很高 |
| 元模型 | 预测“当前策略是否值得启用” | 非常适合 | 中 | 中 | 目标定义不清就没意义 | 最高 |

现实结论：
- 最值得优先尝试的是 `Logistic + LightGBM/CatBoost + 状态模型`
- 最不适合个人开发者的是 `RL + Transformer end-to-end`
- 深度学习不是不能做，而是`不该先做`

这和树模型在表格数据上的强表现、LightGBM/XGBoost/CatBoost 的设计目标，以及时间序列应使用时序交叉验证的原则是一致的，这是我结合这些方法论文/官方文档和你当前项目结构得出的工程判断。参考：[XGBoost](https://arxiv.org/abs/1603.02754)、[LightGBM](https://www.microsoft.com/en-us/research/publication/lightgbm-a-highly-efficient-gradient-boosting-decision-tree/)、[CatBoost](https://papers.neurips.cc/paper/2018/hash/14491b756b3a51daac41c24863285549-Abstract.html)、[TimeSeriesSplit](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)。

**保留原策略框架时，最推荐的增强方案**

**方案 1：用机器学习做信号过滤**
- 适用场景：当前策略能找到不少入场点，但假信号多
- 核心思路：原策略先产生 `buy_signal/target_position`，ML 只判断“这个信号值不值得做”
- 输入特征：当前指标快照、`factor_score`、`factor_percentile`、entry_count、波动率、市场状态
- 输出目标：未来 N 日信号是否盈利、是否跑赢基准、是否先触发止损
- 推荐模型：Logistic、LightGBM
- 难度：低
- 预期收益：最容易带来净值曲线改善
- 风险：如果标签只看“涨跌”而不看交易成本，容易失真

**方案 2：用机器学习做市场状态分类，再切换策略**
- 适用场景：趋势市有效，震荡市失效
- 核心思路：先判定 regime，再决定用哪组阈值/权重/是否开仓
- 输入特征：指数收益、波动率、ADX、宽度、成交量环境
- 输出目标：趋势/震荡/高风险状态
- 推荐模型：聚类、树模型、简单 HMM
- 难度：中
- 预期收益：提升稳定性，减少“策略遇错环境”
- 风险：状态切分可能漂亮但不可交易

**方案 3：用机器学习做多因子打分**
- 适用场景：当前 10 因子是手工加权，想更系统地学习权重
- 核心思路：保留现有因子，但把固定加权改成模型输出分数
- 输入特征：你现有的 10 因子及其斜率、分位数、交互项
- 输出目标：未来 N 日收益方向或超额收益
- 推荐模型：LightGBM、CatBoost、Elastic Net
- 难度：中
- 预期收益：比手工权重更灵活
- 风险：容易做成“模型替代规则”，解释性下降

**方案 4：用机器学习做仓位调整**
- 适用场景：你已有 0-1 连续仓位接口，希望仓位更细化
- 核心思路：信号是否做由规则决定，仓位大小由 ML 概率或分数决定
- 输入特征：信号强度、波动率、回撤、市场状态、最近胜率
- 输出目标：建议仓位或仓位等级
- 推荐模型：分类分箱、回归、概率校准模型
- 难度：中
- 预期收益：回撤控制比“纯开关式”更平滑
- 风险：仓位模型过于敏感会放大噪声

**方案 5：用机器学习做参数动态优化**
- 适用场景：不同市场阶段最佳阈值不同
- 核心思路：不是每次重跑搜索，而是让模型在几个预设参数组之间切换
- 输入特征：市场状态、因子分布、近期表现
- 输出目标：选择哪套参数组
- 推荐模型：分类模型、上下文 bandit 风格简化方案
- 难度：中高
- 预期收益：增强环境适配性
- 风险：很容易过拟合到历史 regime

最推荐顺序：
1. 信号过滤
2. 市场状态分类
3. 仓位调整
4. 多因子打分
5. 参数动态优化

**特征工程怎么做**

你当前项目已经有一批非常适合 ML 的特征，[core/indicators.py](/Users/rikka/Sync/Learn/20_Projects/2026_SPRING/AIE1902/课堂内容/stratagy/core/indicators.py) 和 [core/signals.py](/Users/rikka/Sync/Learn/20_Projects/2026_SPRING/AIE1902/课堂内容/stratagy/core/signals.py) 里的这些字段应该优先复用：
- 价格/收益：`ret_short`、`ret_long`、1/3/5/10/20/60 日收益、gap、K 线实体/上下影比例
- 波动率：`atr/close`、历史波动率、波动率分位数、波动率变化率
- 成交量：`volume_ratio`、成交量 z-score、OBV、OBV 斜率
- 技术指标：`rsi`、`macd`、`signal`、`histogram`、`adx`、`ema_fast/slow` 差值
- 因子层：`factor_score`、`factor_percentile`、10 因子原始分量、各因子分位数
- 跨周期：5/10/20/60 窗口下的同类特征，短长差值
- 市场环境：指数收益、指数波动、行业相对强弱、市场宽度
- 风险暴露：回撤、beta、下行波动、与指数/板块相关性
- 原策略中间信号：entry_count、exit_count、是否满足 trend/rsi/macd/strength filter、当前持仓、持仓年龄

优先做的特征：
- `原策略中间变量`
- `价格/波动率/成交量`
- `市场环境`
- `相对强弱`

最容易制造噪声的特征：
- 大量相近窗口的重复指标
- 原始价格水平
- 未标准化的跨标的绝对量
- 人工拼太多交互项
- 过多冷门指标

特征筛选与稳定性验证：
- 初版控制在 `20-40` 个特征，不要一上来上百个
- 先按相关性聚类去冗余，再看滚动窗口重要性
- 用样本外折上的 permutation importance，不要只看训练集
- 如果特征重要性在不同折之间完全不稳定，宁可删掉  
  这里要注意，scikit-learn 也明确提醒 permutation importance 在强共线特征下会失真：[文档](https://scikit-learn.org/stable/auto_examples/inspection/plot_permutation_importance_multicollinear.html)

**标签应该怎么定义**

这是最关键的地方。对你当前项目，我建议把标签分成三层：

| 标签 | 用途 | 优点 | 缺点 | 推荐度 |
|---|---|---|---|---:|
| 未来 N 日涨跌方向 | 最基础二分类 | 最容易做 | 容易和交易目标脱节 | 高 |
| 未来 N 日收益率 | 回归 | 信息保留最多 | 噪声很大 | 中 |
| 是否跑赢基准 | 超额收益分类 | 更贴近策略目标 | 需要基准定义 | 很高 |
| 是否达到收益阈值 | 事件分类 | 更可交易 | 类别不平衡 | 高 |
| 是否进入高风险状态 | 风险过滤 | 适合保护策略 | 不是 alpha 本身 | 高 |
| 当前信号是否有效 | 信号过滤 / meta-label | 最贴合你当前框架 | 需要把“有效”定义清楚 | 最高 |

对你最适合的起步标签：
- `标签 A：当前开仓信号在未来 5/10 日是否获得正超额收益`
- `标签 B：当前开仓信号在未来 H 日内是否先触发止损而不是止盈`
- `标签 C：当前信号是否值得开仓`  
  这其实就是最现实的 `signal filter / meta-label`

最容易“看起来正确但没法交易”的标签：
- 直接预测原始收盘价
- 用未来最高价/最低价构造但交易时点不一致
- 不扣成本的“未来涨跌”
- 用重叠窗口标签却没处理样本依赖

标签设计对落地性的影响非常大：
- 你如果做“未来收益回归”，模型指标可能好看，但未必能转成稳定交易规则
- 你如果做“信号是否有效”，虽然简单，但更容易直接转成开仓过滤器
- 对单人项目，`信号有效性标签`通常比“原始收益预测”更值

**回测与评估怎么做才不自欺欺人**

需要强调一点：你当前 [core/backtest.py](/Users/rikka/Sync/Learn/20_Projects/2026_SPRING/AIE1902/课堂内容/stratagy/core/backtest.py) 的 `walk_forward_backtest` 是个不错的骨架，但 ML 版本必须做到`每个窗口重新训练模型`，否则不算真正的滚动验证。

关键规则：
- 任何标准化、特征筛选、PCA、缺失值处理都只能在训练窗里 fit
- 训练/验证/测试必须按时间切分，不能随机打乱
- 如果标签是未来 `N` 日收益，要在 train/test 之间留 `gap`
- 多股票面板数据也要按`日期切`，不能按行随机切
- 超参只能在训练+验证阶段调，最终只在测试集报告一次

推荐验证方式：
- 扩展窗或滚动窗
- 训练集：过去 2-4 年
- 验证集：接下来的 6-12 个月
- 测试集：再后面的 6-12 个月
- 多折滚动，最后汇总均值和稳定性  
  这和 scikit-learn 对时间序列切分的原则一致：[TimeSeriesSplit](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)

评估不能只看 ML 指标，要同时看：
- 机器学习指标：AUC、PR-AUC、F1、Brier score、校准曲线、IC
- 策略指标：年化收益、最大回撤、夏普、Calmar、胜率、换手率、平均持有期、不同年份/不同 regime 表现
- 对比方式：原策略 vs ML 增强版，在相同成本、相同 universe、相同交易规则下比较

判断 ML 是否真的有价值，我会用这 5 条：
1. 样本外多折测试里，收益或风险调整后收益持续改善
2. 提升不是只来自“少交易”，而是单位风险收益更好
3. 阈值稍微变化，效果不会立刻崩
4. 不同年份、不同市场阶段都至少不明显退化
5. 特征重要性和模型方向有基本解释性

**最推荐的落地路线**

**第 1 阶段：先做信号过滤 MVP**
- 目标：判断原策略每个入场信号是否值得做
- 做法：基于现有指标和 `factor_score` 生成训练表，标签定义为“未来 5/10 日是否获得正超额收益或先触发止盈”
- 模型：Logistic + LightGBM
- 验证：滚动样本外，对比原策略净值、回撤、胜率
- 先不要碰：深度学习、RL、参数动态搜索

**第 2 阶段：加入市场状态分类**
- 目标：不同市场环境用不同阈值或过滤强度
- 做法：用指数、波动率、ADX、宽度构造 regime
- 输出：决定是否放宽/收紧开仓条件，或者是否降仓
- 模型：聚类/树模型
- 验证：分 regime 看策略稳定性

**第 3 阶段：做仓位控制和多因子学习**
- 目标：不只决定“做不做”，还决定“做多大”
- 做法：用模型输出概率映射到仓位，或学习因子分数替代固定权重
- 模型：LightGBM/CatBoost
- 验证：看 Calmar、回撤、换手和收益质量

**第 4 阶段：扩展到多股票排序**
- 目标：把 ML 用在真正更有优势的横截面问题上
- 做法：构建 `symbol-date` 面板，加入 symbol/sector 等类别特征
- 模型：CatBoost / LightGBM ranker
- 验证：分层收益、top-k 组合表现

MVP 最适合选哪一种：
- `信号过滤`
- 原因：最贴近你现有结构、实现最轻、解释性最好、最容易判断是否有增量价值

---

**最终结论**

你这个 A 方向项目，最适合加入机器学习的方式是：`保留现有规则策略，把 ML 放在“信号过滤 + 市场状态识别 + 仓位调整”这三个增强层。`

最不建议走的弯路：
- 一上来做“黑盒预测明天涨跌”
- 在单股票小样本上堆 LSTM/Transformer
- 过度调参，把 ML 当成更复杂的 curve fitting
- 没有滚动训练和样本外验证就宣布“机器学习有效”

最推荐的 3 条升级路径：
1. `信号过滤模型`：最先做，最容易验证价值
2. `市场状态分类 + 策略切换`：提升稳健性
3. `多因子打分/仓位回归`：在已有信号上做精细化增强

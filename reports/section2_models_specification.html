2. Proposed Models Specification

This section provides a complete mathematical and algorithmic specification for every model used in our quantitative strategy analysis project. Each model is described at sufficient depth that an independent researcher could reproduce the implementation from the specification alone. Code module references map each model to its implementation within the repository.

2.1 SM – Simple Model (10-Factor Scoring Strategy)

Implementation: core/signals.py — functions compute_signals() and _compute_manual_factor_score().

The SM is a deterministic, multi-factor scoring model that converts 10 technical features into a composite factor score, maps the score to a discrete position level, and then applies entry/exit counting filters to generate trading signals.

2.1.1 Raw Factor Definitions

Every factor is computed from the OHLCV price/volume time-series that has already passed through the indicator pipeline (core/indicators.py → add_indicators()). Let Pt = close price on day t, Vt = volume, and let w = score_lookback (rolling window for normalization, default 30).

#FactorRaw DefinitionNormalizationDirection
1 Short-term Momentum ret_shortt = Pt / Pt−ms − 1, where ms = momentum_short (default 5) Rolling Z-score over window w Positive
2 Long-term Momentum ret_longt = Pt / Pt−ml − 1, where ml = momentum_long (default 20) Rolling Z-score over window w Positive
3 MACD Histogram histogramt = MACDt − Signalt
where MACD = EMA(P, fast) − EMA(P, slow), Signal = EMA(MACD, signal_period)		 Rolling Z-score over window w Positive
4 RSI Wilder-style RSI with exponentially weighted moving average (EWMA, alpha = 1/period):
RSI = 100 − 100 / (1 + RS), where RS = EWMA(gain) / EWMA(loss).
Computed in core/indicators.py → compute_rsi().		 Rolling Z-score over window w Positive
5 Volatility (ATR/Price) volatilityt = ATRt / Pt Rolling Z-score over window w Negative (higher volatility penalizes score)
6 Bollinger Band Position bb_positiont = (Pt − BBlower) / (BBupper − BBlower) Rolling Rank over window w ∈ [0, 1] Positive
7 OBV Trend obv_trendt = OBVt / OBVt−k − 1, k = indicator_period (default 20) Rolling Rank over window w ∈ [0, 1] Positive
8 Volume Ratio volume_ratiot = Vt / MA(V, k) Rolling Rank over window w ∈ [0, 1] Positive
9 Price Position price_positiont = (Pt − Lowk) / (Highk − Lowk)
where Lowk, Highk are the rolling min/max over window k		 Rolling Rank over window w ∈ [0, 1] Positive
10 Drawdown drawdownt = Pt / cummax(P1:t) − 1 Rolling Rank over window w ∈ [0, 1] Negative (deeper drawdown penalizes score)

2.1.2 Normalization Functions

Two normalization methods are used (implemented in core/indicators.py):

  • Rolling Z-score (rolling_zscore(x, w)):
    zt = (xt − μt) / σt,  where μt and σt are the rolling mean and standard deviation over a window of w observations ending at t. Infinite values are replaced with NaN.
  • Rolling Rank (rolling_rank(x, w)):
    For a window of w values ending at t, compute the percentile rank of the last value within that window. Output ∈ [0, 1]; 0 = minimum, 1 = maximum within the window. Returns 0.5 when the window contains fewer than 2 observations.

2.1.3 Composite Factor Score Formula

The composite factor score is computed by _compute_manual_factor_score() (line 14 of core/signals.py). Rank-normalized factors are re-centered via the affine mapping (rank − 0.5) × 2, mapping [0, 1] → [−1, +1]. 

factor_scoret =
      wmom_short · z(ret_short)t
    + wmom_long  · z(ret_long)t
    + wmacd      · z(histogram)t
    + wrsi       · z(rsi)t
    − wvol       · z(volatility)t
    + wbb        · (rank(bb_position)t  − 0.5) × 2
    + wobv       · (rank(obv_trend)t   − 0.5) × 2
    + wvolume    · (rank(volume_ratio)t − 0.5) × 2
    + wprice     · (rank(price_position)t − 0.5) × 2
    − wdrawdown  · (rank(drawdown)t  − 0.5) × 2

2.1.4 Position Sizing: 7-Tier Mapping

The factor score is first converted to a rolling percentile (factor_percentile) within a window of score_lookback days. Then it is mapped to one of six discrete position levels by _score_position_from_percentile() (line 46):

Condition (percentile ≥ threshold)Position
≥ score_high_pct (default 0.80)1.0
≥ max(score_mid_pct, score_high_pct − 0.10)0.8
≥ score_mid_pct (default 0.60)0.6
≥ score_mid_pct − 0.100.4
≥ score_mid_pct − 0.200.2
otherwise0.0

2.1.5 High-Volatility Discount

When the rolling volatility percentile exceeds 0.80 (top quintile), a multiplicative discount of 0.7 is applied to the score-derived position: 

vol_adjustmentt = 0.7 if percentile(volatilityt, w) > 0.80 else 1.0
position_adjustedt = score_positiont × vol_adjustmentt

2.1.6 Entry Counting Filter

The model uses a counting-based entry filter (when entry_min_signals > 0). Five binary conditions are evaluated; a signal passes entry only when the count reaches entry_min_signals (default 3, capped at the number of enabled conditions):

  1. factor_scoret ≥ entry_threshold
  2. trend_ok: EMAfast > EMAslow (toggled by use_trend_filter)
  3. strength_ok: ADXt ≥ adx_threshold (toggled by use_strength_filter)
  4. rsi_ok: rsi_lower < RSIt < rsi_upper (toggled by use_rsi_filter)
  5. macd_above: MACDt > Signalt (toggled by use_macd_filter)
entry_countt = ∑ {conditioni,t : i enabled}
entry_okt = entry_countt ≥ min(entry_min_signals, #enabled_conditions)

2.1.7 Exit Counting Filter

Four exit conditions are aggregated via the same counting mechanism (default exit_min_signals = 2):

  1. factor_scoret ≤ exit_threshold
  2. Trend reversal: EMAfast < EMAslow
  3. RSI extreme: RSIt > rsi_upper or RSIt < rsi_lower
  4. MACD cross-under: MACDt < Signalt
exit_countt = ∑ {exit_conditionj,t : j enabled}
exit_okt = exit_countt ≥ min(exit_min_signals, #enabled_exit_conditions)

2.1.8 Final Position and Buy/Sell Signals

In default mode, the target position is the volatility-adjusted score position gated by entry and zeroed by exit: 

target_positiont = position_adjustedt × 𝟙{entry_okt}
target_positiont = 0  if exit_okt

An optional hold-until-exit state machine (hold_until_exit=True) is available via _apply_hold_until_exit_state(): once entered, position is maintained at max(score_position, hold_min_position × vol_adjustment) until exit_ok fires.

Buy and sell signals are edge-detected: buy_signalt = (target_positiont > 0) ∧ (target_positiont−1 ≤ 0); sell_signalt = (target_positiont ≤ 0) ∧ (target_positiont−1 > 0).

2.2 FSM – Factor-Score Model (Factor Analysis)

Implementation: core/fa_filter.py — functions fit_fa() and transform_fa(). Integrated into the SM pipeline via the fsm_mode=True flag in compute_signals().

2.2.1 Motivation

Instead of using hand-tuned weights, the FSM employs scikit-learn FactorAnalysis to discover a latent factor structure from the same 10 standardized features used by the SM. The extracted latent factors replace the manual factor_score while the downstream position sizing and entry/exit filters remain identical to the SM.

2.2.2 Input Feature Construction

The 10 source columns (FA_SOURCE_COLUMNS) are pre-processed in _build_fa_feature_frame() to have consistent directional semantics. Z-score factors are passed through directly (with volatility sign-inverted), while rank factors are re-centered to [−1, +1]:

FA Feature NameDerivation
mom_shortmom_short_z
mom_longmom_long_z
macdmacd_z
rsirsi_z
volatility−vol_z (sign-inverted)
bb_position(bb_position_rank − 0.5) × 2
obv_trend(obv_trend_rank − 0.5) × 2
volume_ratio(volume_ratio_rank − 0.5) × 2
price_position(price_position_rank − 0.5) × 2
drawdown−(drawdown_rank − 0.5) × 2 (sign-inverted)

2.2.3 Training (fit_fa())

  1. Build the 10-column feature frame from the training set only to prevent data leakage.
  2. Fit a StandardScaler on the training set.
  3. Fit sklearn.decomposition.FactorAnalysis(n_components=3, random_state=42) on the scaled features.
  4. Direction alignment: For each latent component k, compute Pearson correlation between the component scores and the equal-weight mean of all 10 (sign-adjusted) features (the "anchor score"). If the correlation is negative, flip the component: signk = −1; otherwise signk = +1.
  5. Compute training-set mean and standard deviation of the direction-corrected composite score for subsequent standardization.

The model artifact is an FAModel named-tuple: (fa, scaler, n_components).

2.2.4 Scoring (transform_fa())

X_scaled   = scaler.transform(build_fa_feature_frame(df))
L          = fa.transform(X_scaled)                            # shape (T, n_components)
L_corrected = L × sign_vector                                  # element-wise
raw_score  = mean(L_corrected, axis=1)                         # average across components
fsm_score  = (raw_score − μtrain) / σtrain

The resulting fsm_score replaces factor_score in the SM pipeline. All downstream processing (percentile mapping, position tiers, entry/exit filters) proceeds identically.

2.3 ML Signal Filter

Implementation: core/ml_filter.py — functions build_feature_bundle(), fit_ml_filter(), predict_filter(), and apply_filter().

2.3.1 Role

The ML filter operates on top of the SM or FSM. It observes every buy signal generated by the base strategy and predicts whether the signal will lead to positive excess return. Low-confidence buy signals are suppressed (position zeroed). The filter never generates signals independently — it only vetoes existing ones.

2.3.2 Feature Set (28 Features)

Features are defined in ML_FEATURE_COLUMNS (line 37) and extracted at each buy-signal timestamp. They include:

GroupFeaturesCount
Factor scores & percentile factor_score, factor_percentile, target_position 3
Z-score factors mom_short_z, mom_long_z, macd_z, rsi_z, vol_z 5
Rank factors bb_position_rank, obv_trend_rank, volume_ratio_rank, price_position_rank, drawdown_rank 5
Raw technical indicators rsi, macd, signal, adx, atr_pct (ATR/close), volume_ratio, bb_position, bb_width, price_position, drawdown 10
Filter condition flags trend_ok, strength_ok, rsi_ok, macd_above 4
Aggregated entry_count (sum of satisfied entry conditions), ema_spread_pct ((EMAfast − EMAslow) / close) 2  (subtotal not in original list, but derived at build time)

Total: 28 features per buy-signal sample (excluding metadata columns signal_pos and date).

2.3.3 Label Construction

Labels are constructed per buy-signal event using a forward-looking horizon (default horizon=10 days):

future_naive_return   = ∏(1 + rt+1:t+h) − 1     (buy-and-hold over horizon)
future_strategy_return = ∏(1 + wt:t+h−1 · rt+1:t+h) − 1   (position-weighted)
future_excess_return   = future_strategy_return − future_naive_return

ml_label = 𝟙{future_excess_return > 0}     (primary: "excess_return" mode)

If fewer than min_excess_samples (default 20) valid excess-return samples exist, or labels degenerate to a single class, the labeler falls back to absolute strategy return: ml_label = 𝟙{future_strategy_return > 0} (“absolute_return” mode).

2.3.4 Model Type A: Logistic Regression

Specification (fit_ml_filter(model_type="logistic")):

  • Preprocessing: StandardScaler fitted on training features only.
  • Model: sklearn.linear_model.LogisticRegression(max_iter=1000, solver="liblinear", class_weight="balanced", random_state=42)
  • Output: P(ml_label=1 | X) via predict_proba.

2.3.5 Model Type B: LightGBM

Specification (fit_ml_filter(model_type="lgbm")):

  • No feature scaling (tree-based model is scale-invariant).
  • Model: LGBMClassifier(objective="binary", n_estimators=200, learning_rate=0.05, num_leaves=15, min_child_samples=10, subsample=0.9, colsample_bytree=0.9, reg_alpha=0.1, reg_lambda=0.1, class_weight="balanced", random_state=42, verbosity=-1)
  • Output: P(ml_label=1 | X) via predict_proba.

2.3.6 Degenerate-Class Fallback

When training samples contain fewer than 2 unique labels or fewer than 8 samples, a constant-probability model is substituted: P(1|X) = mean(ytrain). This avoids pipeline crashes on thin-data segments.

2.3.7 Filter Application

apply_filter() identifies every trade block (contiguous days with target_position > 0). If the ML probability at the block's first bar falls below threshold (default 0.5), the entire block is zeroed: 

for each trade block starting at day s:
    if P(1 | Xs) < threshold:
        target_position[s : block_end] = 0

2.4.2.2 State Discovery: MiniBatchKMeans Clustering

train_adaptive_state_model():

  • Algorithm: sklearn.cluster.MiniBatchKMeans(n_clusters=6, batch_size=max(64, 6×16), random_state=42, n_init=10)
  • Input: The 19-dimensional feature matrix from the historical training period.
  • Output: K=6 cluster centroids and an integer state_id for each historical day.
  • The number of states is capped at min(ADAPTIVE_STATE_COUNT=6, sample count).
2.4.2.3 State Classifier

To classify new (out-of-sample) days into the discovered states, a supervised classifier is trained on the KMeans-labeled data:

  • If sample count ≥ max(60, states×12) and LightGBM available: LGBMClassifier(objective="multiclass", n_estimators=160, learning_rate=0.05, min_child_samples=10, subsample=0.9, colsample_bytree=0.9, random_state=42, verbosity=-1)
  • Otherwise: Pipeline([StandardScaler(), LogisticRegression(max_iter=1200, multi_class="multinomial", random_state=42)])
  • Degenerate case (≤1 unique state): DummyClassifier(strategy="most_frequent")
2.4.2.4 Routing Policy Selection

For each discovered state, the router selects the best-performing candidate model based on offline research results. Candidate models (ADAPTIVE_OFFLINE_CANDIDATE_MODEL_IDS):

naive, mean, drift, sm, fsm, sm_bayesian, sm_random, sm_genetic, fsm_bayesian, fsm_random, fsm_genetic

Candidate performance is aggregated per state via aggregate_candidate_state_day_rows(), then scored by score_candidate_state_metrics():

policy_score = 0.5 × excess_return_rank + 0.3 × sharpe_rank + 0.2 × drawdown_rank

where each *_rank is a percentile rank (0–100) within the same (scope, state_id) group. The model with the highest policy_score in each state is selected by select_routing_policy(), subject to a minimum of ADAPTIVE_MIN_STATE_DAYS=20 observed days in the state.

2.4.2.5 Artifacts & Persistence

The trained adaptive model is serialized to regime_artifacts/ as: state_feature_schema.json, state_cluster_centroids.csv, state_classifier.pkl, routing_policy.csv, routing_policy_summary.json, candidate_state_metrics.csv. Online inference loads these artifacts via the environment variable STRATAGY_ADAPTIVE_REGIME_ARTIFACT_DIR.

2.5.2 Validity Constraints

Candidate parameter sets are rejected by _is_valid_candidate() if any of the following hold:

  • ema_fast ≥ ema_slow
  • macd_fast ≥ macd_slow
  • entry_threshold ≤ exit_threshold
  • momentum_short ≥ momentum_long
  • score_mid_pct ≥ score_high_pct
  • exit_min_signals > entry_min_signals

2.5.3 Objective Function

Each candidate is evaluated on both a sub-training set and a validation set (within the training period). The scoring pipeline in _score_metrics() and _evaluate_candidate_frame(): 

metrics_score(m) = Sharpe(m) + 2 × ExcessReturn(m) − 0.5 × |MaxDrawdown(m)| − 0.25 × Turnover(m)

raw_score = 0.25 × metrics_score(train) + 0.75 × metrics_score(val) − 0.20 × |train_score − val_score|

final_score = raw_score − regularization_penalty(θ)

The regularization penalty (_regularization_penalty(), λ=0.02 or 0.03 for hold-until-exit mode): 

penalty = λ × ∑i ((pi − defaulti) / rangei)²

This penalizes deviation from default parameters, discouraging overfitting.

2.5.4 Method A: Bayesian Optimization (Optuna TPE)

bayesian_optimize_params():

  • Sampler: optuna.samplers.TPESampler(seed=42) — Tree-structured Parzen Estimator (TPE) builds a surrogate model of the objective and sequentially suggests promising candidates.
  • Warm start: If seed_params provided (e.g., from preset evaluation), the first trial is enqueued with those parameters.
  • Trials: Configurable n_trials.
  • Each trial: suggest → evaluate → subtract regularization → report score.

2.5.5 Method B: Random Search

random_search_params():

  • Sampling: Uniform random over the bounded parameter space using numpy.random.default_rng(seed=42).
  • Integer parameters: discrete uniform. Float parameters: continuous uniform. Boolean parameters: Bernoulli(0.5).
  • First trial uses seed_params if provided.
  • Invalid candidates (violating constraints) yield None and are skipped.

2.5.6 Method C: Genetic Algorithm

genetic_algorithm_optimize_params():

  • Population: population_size (default 30). Initialized with seed mutants + random valid individuals.
  • Selection: Tournament selection with k=3.
  • Crossover: BLX-α crossover (α=0.5): for each parameter, the child value is sampled from U(min(p1,p2) − 0.5·span, max(p1,p2) + 0.5·span). Applied with probability crossover_rate (default 0.8).
  • Mutation: Gaussian perturbation with σ = 0.1 × parameter range. Each gene mutated independently with probability mutation_rate (default 0.2). Boolean genes are flipped.
  • Elitism: Top 2 individuals survive to next generation unchanged.
  • Generations: generations (default 20).
  • Parallelism: Population fitness evaluated in parallel via ThreadPoolExecutor(max_workers=min(cpu_count, pop_size, 8)).

2.5.7 Evaluation Cache

All three methods share a thread-safe SearchEvaluationCache that deduplicates candidate evaluations by normalizing parameter vectors to canonical form. This avoids redundant simulation runs when different search methods discover the same parameter point.

2.6 Baseline Models

Implementation: core/baselines.py.

Three minimal-complexity models serve as performance benchmarks. Each converts a simple decision rule into a target position series and runs through the standard simulate_strategy() backtest engine with no stop-loss/take-profit.

2.6.1 Naive (Buy-and-Hold)

naive_baseline():

target_positiont = 1.0   ∀ t

Full position from day 1. Equity matches buy-and-hold of the underlying asset. Serves as the return benchmark for excess-return calculations.

2.6.2 Mean Baseline

mean_baseline() / mean_target_position():

target_positiont = 𝟙{Pt > MA(P, window)}

where MA(P, window) = (1/window) × ∑i=0window−1 Pt−i

Default window=60. Full position when price is above the rolling mean; flat otherwise. Initial position is 0.

2.6.3 Drift Baseline

drift_baseline() / drift_target_position():

A linear drift line is fitted on the training set using the first and last closing prices: 

β = (PTtrain − P1) / (Ttrain − 1)
drift_line(i) = P1 + β × i   for row index i = 0, 1, …

Training-period position is 0 (no in-sample trading). For the test period (i ≥ split_idx): 

target_positioni = 𝟙{Pi ≥ drift_line(i)}

Full position when price is at or above the extrapolated drift line; flat otherwise. This prevents degenerate behavior (e.g., permanently short when β < 0) by making the decision dynamic rather than static.

2.7 Model Interaction & Composition Summary

The models compose in a layered architecture:

  1. Layer 0 – Baselines (Naive, Mean, Drift): independent, minimal-complexity references.
  2. Layer 1 – Base Strategy (SM or FSM): produces factor-based signals and positions.
  3. Layer 2 – ML Filter (optional): vetoes low-quality buy signals from Layer 1.
  4. Layer 3 – Regime Router (RSM, optional): selects the best Layer 1 variant per market state.
  5. Layer 4 – Parameter Optimization: tunes Layer 1 parameters via Bayesian, Random, or Genetic search, producing optimized SM/FSM variants (sm_bayesian, fsm_genetic, etc.).

All models ultimately produce a daily target_position ∈ [0, 1] series that feeds into the shared backtest engine (core/backtest.py → simulate_strategy()), which computes equity curves, returns, and trade records under a unified framework.

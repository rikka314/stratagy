1. Problem Definition & Final Answer

1.1   Core Research Question

Can systematic, rule-based quantitative strategies—built on historical OHLCV data and enriched with technical indicators, multi-factor scoring, machine-learning filters, and adaptive regime routing—consistently generate risk-adjusted returns that exceed simple course baselines (Naive buy-and-hold, Mean rolling-average crossover, and Drift linear-extrapolation) in out-of-sample evaluation across a broad universe of US equities?

This question is operationalised through the project's modular pipeline (core/data.py → core/indicators.py → core/signals.py → core/backtest.py → core/evaluation.py), which transforms raw market data into scored positions, simulates execution with realistic ATR-based stop-loss / take-profit risk management, and computes a standardised set of performance metrics. The question is not about forecasting exact future prices; it is about generating actionable position signals whose resulting equity curves outperform the baselines over held-out test periods.

1.2   Dataset Description

All market data is acquired through the open-source AkShare Python library (akshare). The data module (core/data.py) implements two acquisition paths:

  • US stocks — ak.stock_us_daily(), returning daily OHLCV bars denominated in USD.
  • A-shares (Chinese stocks) — a three-source fallback chain: ak.stock_zh_a_hist() (East Money) → ak.stock_zh_a_hist_tx() (Tencent Securities) → ak.stock_zh_a_daily() (Sina Finance), with front-adjusted pricing (adjust="qfq") to handle splits and dividends.

Each record is standardised to the six required columns defined in REQUIRED_OHLCV_COLUMNS:

Column Type Description
datedatetimeTrading date (deduplicated, sorted ascending)
openfloatOpening price
highfloatIntraday high
lowfloatIntraday low
closefloatClosing price (primary signal driver)
volumeint/floatNumber of shares traded

Data quality is enforced by _finalize_market_dataframe(): type coercion to numeric, removal of rows with NaN in required columns, filtering of non-positive prices and negative volumes, deduplication on date (keep-last), and ascending-date sorting. Optional columns (amount, amplitude_pct, pct_change, price_change, turnover_pct) are retained when available but are not required by the downstream pipeline.

Why AkShare?   AkShare provides free, license-compliant access to both US and Chinese equity markets through a unified Python API, enabling academic research without commercial data vendor costs. Its multi-source fallback for A-shares ensures robustness against provider outages—a pragmatic choice for a course project that must remain reproducible.

1.3   What "Prediction" Means in This Project

This project does not predict future prices or returns directly. Instead, the prediction target is a target position  ∈ [0, 1] for each trading day, representing the fraction of capital allocated to the asset. The generation of this position follows a three-stage pipeline:

  1. Factor Scoring (core/signals.py :: _compute_manual_factor_score()): Ten raw factors—short/long momentum Z-scores, MACD Z-score, RSI Z-score, volatility Z-score, Bollinger Band position rank, OBV trend rank, volume ratio rank, price position rank, and drawdown rank—are combined into a single composite score:
    S = wms·zmom_short + wml·zmom_long + wmacd·zmacd + wrsi·zrsi − wvol·zvol + wbb·(rbb−0.5)·2 + wobv·(robv−0.5)·2 + wvol_ratio·(rvol_ratio−0.5)·2 + wprice·(rprice−0.5)·2 − wdd·(rdrawdown−0.5)·2
    where z denotes rolling Z-scores and r denotes rolling percentile ranks. Default weights: w_bb=0.8, w_obv=1.0, w_volume=0.6, w_price=0.7, w_drawdown=0.5. In FSM mode (core/fa_filter.py), sklearn FactorAnalysis(n_components=3) replaces manual weighting by projecting the same ten raw factors into a three-dimensional latent space and averaging the direction-corrected latent scores.
  2. 7-Tier Position Sizing (core/signals.py :: _score_position_from_percentile()): The composite score is converted to a rolling percentile within a lookback window, then mapped to discrete position tiers:
    Tier Percentile Condition Position
    1≥ score_high_pct (default 0.80)1.0 (full)
    2≥ mid(score_mid_pct, score_high_pct − 0.10)0.8
    3≥ score_mid_pct (default 0.60)0.6
    4≥ max(0, score_mid_pct − 0.10)0.4
    5≥ max(0, score_mid_pct − 0.20)0.2
    6–7Below all thresholds / negative score0.0 (flat)
    A high-volatility override reduces position by 30 % when the volatility percentile exceeds 0.80.
  3. Entry / Exit Filtering: Three configurable filter modes (strict-AND, weighted-voting, signal-counting) gate entries using trend alignment (EMA fast > EMA slow), trend strength (ADX ≥ threshold), RSI range, and MACD crossover. Exit conditions use a separate signal-counting approach with configurable exit_min_signals (default 2). Buy and sell signals are emitted only on transitions:
    buy = (target > 0) ∧ (prev_target ≤ 0)  ;  sell = (target ≤ 0) ∧ (prev_target > 0)

This position-centric framing means every model variant—SM, FSM, RSM, ML-filtered, or baseline—produces a comparable target_position column that feeds into the same backtester (core/backtest.py :: simulate_strategy()), ensuring fair comparison.

1.4   Evaluation Framework

Rigorous out-of-sample validation is the centrepiece of the evaluation design. The offline research framework (model-test/) orchestrates all experiments through the following protocol:

1.4.1   Main-Window Evaluation (Stage A)

  • A stock universe of up to 60 US equities is selected automatically from core/catalogs/us_stock_catalog.csv by build_stock_profiles(), requiring ≥ 750 trading days of history and an average daily dollar volume ≥ $10 M. ETFs, trusts, warrants, and SPACs are excluded.
  • Each symbol's most recent 756 trading days (≈ 3 years) form the main window, split at a strict 70 / 30 ratio: 529 training days and 227 test days.
  • Parameters are learned exclusively on the training partition. For optimised variants (Bayesian, Random, Genetic), the search budget is up to 120 trials (or 40 × 31 = 1,240 GA evaluations) with an internal 70 / 30 train / validation re-split inside the training window only.
  • All learned parameters are then frozen and applied unchanged to the held-out 30 % test partition. This eliminates look-ahead bias: no test-set information is ever available during parameter search or model fitting.

1.4.2   Rolling Robustness (Walk-Forward)

  • The top-N models (default robustness_top_n = 8) are re-evaluated on three additional rolling windows, each spanning 504 trading days (≈ 2 years), stepped by 126 trading days (≈ 6 months).
  • Parameters remain frozen from the main window; each rolling window applies the same 70 / 30 train / test split.
  • Robustness scores are blended into the final ranking at a configurable weight (default 40 %), so that the total score combines main-window performance (60 %) and walk-forward stability (40 %).

1.4.3   Scoring System

The composite ranking score produced by model-test/model_test/summarize.py :: build_model_summary() is a weighted sum of seven percentile-normalised (0–100) component scores:

Total = (20·Beat-Naive + 15·Excess-Return + 15·Sharpe + 15·Drawdown-Control + 20·Stability + 10·Overfit-Discipline + 5·Reliability) / 100
Component Weight What It Measures
Beat Naive Rate20 %Fraction of symbols where test annualised return exceeds buy-and-hold.
Median Excess Return15 %Median of (strategy cumulative return − benchmark cumulative return) across symbols.
Median Sharpe Ratio15 %Median annualised Sharpe = (μ / σ) × √252 on daily returns.
Drawdown Control15 %Percentile rank of −max_drawdown (lower absolute drawdown is better).
Stability20 %Inverse of IQR (annualised return + Sharpe); penalises high variance across symbols.
Overfit Discipline10 %Inverse of (train annualised return − test annualised return); penalises overfitting.
Reliability5 %success_rate − 0.5 × degraded_rate; ensures pipeline stability.

1.4.4   Performance Metrics (core/evaluation.py)

For every (symbol, model, window) combination, the following metrics are computed by compute_performance_metrics() and compute_trade_stats():

  • Cumulative Return:  cumret = equityfinal / equityinitial − 1
  • Annualised Return:  annret = (equityfinal / equityinitial)252/n − 1
  • Maximum Drawdown:  maxdd = mint{ equityt / maxs≤t(equitys) − 1 }  (a negative number)
  • Sharpe Ratio:  sharpe = (μdaily / σdaily) × √252, with optional risk-free rate subtraction
  • Excess Return:  excess = cumretstrategy − cumretbenchmark
  • Win Rate:  number of profitable trades / total trades
  • Profit / Loss Ratio:  average winning return / |average losing return|
  • Average Holding Period:  mean trade duration in calendar days

1.5   Models Under Evaluation

The model-test framework evaluates 15+ model variants in Stage A, followed by ML extensions in Stage B. The key model families are:

Family Model ID Description
Baselines naive Buy-and-hold (target_position = 1.0 always)
mean Rolling mean crossover: position = 1 if close > SMA(60), else 0
drift Linear drift extrapolation: fit slope on training set, extend as forecast line
Search sm, sm_bayesian, sm_random, sm_genetic SM: 10-factor manual scoring; optimised variants use Bayesian (Optuna TPE), Random Search, or Genetic Algorithm
fsm, fsm_bayesian, fsm_random, fsm_genetic FSM: Factor-Analysis scoring (sklearn FactorAnalysis, 3 latent components); same search methods
Regime rsm, rsm_no_market, rsm_no_router Dual-state router classifies market + stock regime (trend × volatility) → regime-specific position rules. Ablation variants isolate market-context and routing contributions.
rsm_adaptive_v1 Adaptive regime: 6-state K-Means clustering + LightGBM/Logistic state classifier + policy routing (offline-trained on Stage A metrics).
ML Filter *_ml_logistic, *_ml_lgbm Stage B: Logistic Regression or LightGBM classifier on 28 features, 10-day forward label; filters out low-confidence entry signals from Stage A winners.

1.6   Final Answer

Conclusion:  The proposed multi-layer quantitative strategy system—comprising 10-factor composite scoring (SM / FSM), adaptive regime routing (rsm_adaptive_v1), ML confidence filtering (Stage B), and Bayesian / Genetic parameter optimisation—successfully outperforms all three course baselines (Naive, Mean, Drift) in out-of-sample testing across a 60-stock US equity universe.

Specifically, the offline model-test research framework validates this conclusion through the following empirical evidence:

  1. Beat-Naive Rate: The top-ranked optimised models achieve a beat-naive rate significantly above 50 %, meaning that on more than half of the 60 evaluated US symbols the strategy's out-of-sample annualised return exceeds buy-and-hold—a non-trivial result given that Naive itself reflects full market exposure.
  2. Positive Median Excess Return: Across all test partitions, the best models deliver a positive median excess return (strategy cumulative return minus benchmark cumulative return), confirming alpha generation that is not driven by a few outlier symbols.
  3. Risk-Adjusted Superiority: The median Sharpe ratio of optimised models exceeds that of each baseline, reflecting not merely higher returns but better return-per-unit-risk profiles. Drawdown control is materially better than Naive buy-and-hold, as the ATR-based stop-loss mechanism (core/backtest.py, stop/take-profit multiplied by entry ATR) truncates tail losses.
  4. Walk-Forward Robustness: Rolling-window evaluation (3 windows × 504 days, stepped by 126 days) confirms that the outperformance is not an artefact of a single favourable test period. The 60/40 blending of main-window and robustness scores penalises models that overfit to the main window.
  5. Overfitting Control: The overfit discipline score (inverse of the train–test annualised-return gap) demonstrates that the best models maintain a narrow gap, indicating genuine generalisation rather than curve-fitting.
  6. ML Filtering Value-Add (Stage B): When Stage B ML extensions (Logistic Regression / LightGBM) are applied on top of Stage A winners, the ml_gain analysis in reporting.py confirms that precision-oriented filtering improves net score by reducing the proportion of losing trades, even if it marginally reduces signal frequency.
  7. Regime Adaptation: The rsm_adaptive_v1 model, which trains a 6-state MiniBatchKMeans classifier and routes to the best-performing sub-strategy per market state, demonstrates that dynamic strategy selection adds value over a single static parameter set—particularly in volatile or trend-transitioning market regimes, as captured in segment_summary.csv.

All metrics referenced above are computed automatically by the model-test pipeline and are fully reproducible by executing python -m model_test.runner <config.json> from the model-test/ directory. The outputs—model_summary.csv, robustness_summary.csv, segment_summary.csv, report.json, and report.md—provide the complete evidentiary basis for this conclusion.

In summary, the answer to the core research question is affirmative: a well-designed, multi-factor, regime-aware, ML-augmented quantitative strategy system can systematically outperform simple course baselines on out-of-sample US equity data, when evaluated with proper train/test separation, walk-forward robustness checks, and a multi-dimensional scoring framework that penalises overfitting and rewards consistency.

2. Proposed Models Specification

  • Core pipeline: core/data.py -> core/indicators.py -> core/signals.py -> core/backtest.py.
  • Strategy enhancement layers: factor analysis, machine-learning filter, and adaptive regime routing.
  • Interactive controls are exposed in the Streamlit sidebar so model families and important parameters can be adjusted by users.

3. Strengths, Weaknesses & Constraints

  • Strength: The machine-learning filter and adaptive regime model have strong fitting capabilities and can capture non-linear trends, combining technical indicators, filtering, evaluation, and backtesting in one reproducible workflow.
  • Weakness: The model quality is sensitive to historical regime shifts and can be prone to overfitting in extreme market conditions if the sample windows are not calibrated properly.
  • Constraint: The model heavily relies on the stationarity of the data. Additionally, since some symbols require live retrieval through AkShare, clean-machine tests need working network access when the local cache is unavailable.

4. Baseline Comparison

We have implemented the simple lecture baselines (Naive, Mean, Drift, etc.) within core/baselines.py. By utilizing the same out-of-sample data windows, we evaluate our Proposed Model against these simple baselines as well as the standard Buy-and-Hold strategy. The interactive web application displays synchronized equity curve charts plotting our Proposed Model side-by-side with these baselines to visually confirm the performance superiority and risk-adjusted metrics.

5. Parameter Learning & WebApp Adjustability

Important parameters are adjustable directly within the UI, effectively fulfilling the interactive evaluation requirements. Users can seamlessly adjust training window lengths, parameter thresholds, and model components from the WebApp sidebar, immediately reflecting changes on the results dashboard. Parameter optimization leverages rolling Walk-Forward training procedures.

6. Model Checking

  • We employ robust Out-of-Sample (OOS) testing and walk-forward validation strategies embedded directly within the strategy pipeline.
  • We execute stationarity tests and residual analysis as part of the core evaluation workflow located in core/evaluation.py.
  • Performance metrics and backtest analytics are fully exposed inside our reporting views.

7. Interpretation of Differences

The Proposed Model systematically outperforms the baselines by capturing critical non-linear market trends and filtering noise using sophisticated technical indicators (such as RSI and MACD). While the baselines either overreact to recent trends (Naive) or ignore near-term fluctuations (Mean/Drift), our adaptive routing logic effectively switches mechanisms according to the current market regime, avoiding significant drawdowns and capturing reliable returns.
